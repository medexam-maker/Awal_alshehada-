Interactive Learning Patterns Master Specification

Interactive Learning Patterns Master Specification

Contract 1 — Adaptive Grammar Lab

المختبر النحوي التكيفي

Project: Awal Al-Shehada — Sudanese Secondary Certificate Examination Platform
Contract: C1 — Adaptive Grammar Lab
Status: Proposed Detailed Functional Contract
Scope: Grammar and sentence-parsing learning pattern
Implementation Rule: Existing architecture and frozen contracts C1–C9 v1.1.0 remain authoritative.

---

1. Purpose and Vision

The Adaptive Grammar Lab transforms the existing grammar question pattern into an interactive learning experience that supports both formal examination and guided learning.

It must not become a separate examination engine or introduce a new question type outside the platform's existing 15 approved question types.

The objective is to help students:

1. Answer grammar questions using the methods expected in the Sudanese Secondary Certificate Examination.
2. Understand why an answer is correct or incorrect.
3. Develop grammatical reasoning progressively.
4. Identify specific grammatical concepts they have mastered or need to improve.
5. Review previously misunderstood concepts through appropriate exercises over time.

The system must measure mastery of individual grammatical skills rather than assigning only one general grammar proficiency score.

Core principle: The platform must teach the student how to understand grammatical structure, not merely memorize the correct answer.

2. Scope and Boundaries

This contract covers the educational and interactive behavior of the Adaptive Grammar Lab.

It includes:

- Interactive sentence analysis.
- Word selection and highlighting.
- Grammatical role identification.
- Case and grammatical-mark identification.
- Explanation of grammatical reasoning.
- Progressive hints.
- Partial-credit assessment where configured.
- Guided training activities.
- Formal examination behavior.
- Skill-level performance tracking.
- Integration with the future mastery and spaced-repetition system.

It does not authorize:

- Creating a separate examination engine.
- Adding a new question type outside the existing 15 approved types.
- Replacing the current examination lifecycle.
- Changing frozen architectural contracts.
- Introducing a new database schema without explicit approval.
- Allowing AI to determine official answer keys or official examination grades.
- Implementing XP, badges, leaderboards, or a gamification system in this phase.

3. Two Separate Experiences

The grammar pattern must support two distinct experiences:

3.1 Training Mode — Interactive Grammar Learning

Training is an educational experience, not a formal examination.

It may provide:

- Immediate feedback.
- Progressive hints.
- Explanations.
- Interactive sentence analysis.
- Partial correction.
- Guided learning steps.
- Remedial exercises.
- Skill tracking.
- Recommendations for later review.

The student should be allowed to make mistakes and learn from them without being blocked from continuing to other concepts.

3.2 Simulator Mode — Formal Examination

Simulator mode must preserve the existing formal examination rules.

During an active examination:

- No hints are permitted.
- No correct-answer disclosure is permitted.
- No remedial learning paths are permitted.
- No immediate correctness feedback is permitted.
- No adaptive difficulty changes are permitted.
- No additional API requests are permitted.
- The student must not receive information that reveals the correct answer before submission.

The official result must be calculated by the server after submission.

The grammar interface must not weaken or bypass the platform's existing examination lifecycle:

START → snapshot → zero API requests during active examination → finish → server-side grading.

4. Core Interactive Grammar Experience

The system should support several complementary interaction methods.

These are interaction methods within the existing grammar pattern, not separate question types.

4.1 Click-to-Select Words

The student can click or tap any selectable word in the sentence.

The selected word should be visually distinguished from the remaining sentence.

The system should support:

- Selecting one word.
- Changing the selected word.
- Removing the selection.
- Selecting another word without losing the sentence context.
- Clear visual indication of the current selection.

The interaction must work on mobile touchscreens without requiring a mouse.

4.2 Text Highlighting

The student may highlight a word or a configured text segment.

Highlighting can be used to:

- Identify the grammatical subject.
- Identify the predicate.
- Locate an object.
- Distinguish grammatical particles.
- Identify a noun governed by a preposition.
- Mark other grammatical structures supported by the authored question.

The visual highlighting must remain readable and must not interfere with Arabic letter shaping, diacritics, or text direction.

4.3 Semantic Coloring

The training interface may use semantic colors to distinguish grammatical roles.

For example:

- Subject.
- Predicate.
- Object.
- Verb.
- Particle.
- Governed noun.

The exact color mapping should be configurable and consistently applied.

Colors must not be the only way to communicate meaning. Every distinction must remain understandable through text labels, symbols, or other accessible indicators.

In simulator mode, colors must not reveal the correct grammatical classification.

4.4 Drag-and-Drop Cards

The system may provide optional draggable grammar cards.

Examples:

- الفاعل
- المفعول به
- المبتدأ
- الخبر
- النعت
- الحال

The student can associate a card with a word or sentence segment.

However:

- Drag-and-drop must never be the only available interaction.
- An equivalent tap-to-select and tap-to-assign interaction must be available.
- Mobile usability must be tested.
- Dragging must not accidentally scroll the page or make the interface difficult to use.

5. Three Levels of Grammatical Analysis

The training experience should support progressively deeper analysis.

These levels describe the depth of learning and do not create additional examination modes.

Level 1 — Basic Identification

The student identifies the grammatical role of a selected word.

Examples:

- Identify the subject.
- Identify the object.
- Identify the predicate.
- Identify a prepositional phrase.

The objective is to recognize the grammatical function.

Level 2 — Grammatical Case and Mark

The student identifies:

- The grammatical case.
- The grammatical mark.
- Whether the mark is original or secondary, where relevant.
- The grammatical reason for the mark.

Examples include:

- مرفوع بالضمة.
- منصوب بالفتحة.
- مجرور بالكسرة.
- مرفوع بالواو.
- منصوب بالياء.

The system must use the correct grammatical terminology and must not accept an incorrect grammatical explanation merely because the student selected the correct role.

Level 3 — Full Sentence Analysis

The student analyzes the complete sentence.

Depending on the authored exercise, this may include:

- Identifying the sentence structure.
- Identifying grammatical relationships.
- Classifying words.
- Determining grammatical cases.
- Identifying grammatical marks.
- Explaining the grammatical reason.
- Understanding the effect of grammatical particles and operators.

The system must allow an exercise to assess only the relevant components. It must not force every question to require all three levels.

6. Progressive Hints and Guided Learning

Training mode should support progressive hints.

Hints must be authored or approved by the content administrator.

The system must not generate unverified grammatical rules or explanations dynamically and present them as authoritative.

A possible hint sequence:

Hint 1 — General Direction

Guide the student toward the relevant grammatical concept.

Hint 2 — Structural Clue

Help the student identify the relationship between words.

Hint 3 — More Specific Guidance

Narrow down the grammatical possibilities without immediately revealing the answer.

Final Explanation

After the answer is submitted or the configured learning sequence is completed, show the correct answer and its explanation.

The number of hints and their content must be configurable for each exercise.

Hints are unavailable during formal simulation.

7. Partial-Credit Assessment

The grammar pattern should support partial assessment when the question is designed to measure multiple independent components.

For example, a configured exercise may evaluate:

Component| Assessment
Correct grammatical role| Separate score
Correct grammatical case| Separate score
Correct grammatical mark| Separate score
Correct grammatical reasoning| Separate score

The exact marks and weighting must be defined by the question author or the existing approved scoring configuration.

Important rules:

- Do not invent a universal scoring formula.
- Do not award full marks merely because one component is correct.
- Do not penalize a student twice for the same underlying error unless the approved marking scheme explicitly requires it.
- The official grading result must use the approved answer key and server-side scoring rules.
- Partial feedback in training must not alter the official examination grading contract.

8. Mastery Path — Individual Grammatical Skill Tracking

The platform should measure the student's progress for individual grammatical concepts.

A single overall grammar percentage is insufficient.

Example of a conceptual skill map:

Grammatical Skill| Illustrative Mastery
الفاعل| 95%
المفعول به| 80%
المبتدأ والخبر| 65%
النواسخ| 40%
الأسماء الخمسة| 25%

These percentages are illustrative only, not predefined thresholds or an approved mastery algorithm.

The system should distinguish between different skills and identify the specific concepts requiring further practice.

8.1 Skill Association

Each eligible training exercise should be associated with one or more grammatical skills.

The association must be defined through the existing content-authoring and assessment mechanisms, after the technical audit confirms how these are represented in the current project.

A question may assess multiple skills, but the system must not assign skill associations through unreliable text guessing.

8.2 Mastery Evidence

Mastery should be estimated using multiple evidence points where supported by the existing data model and approved rules.

Potential evidence includes:

- Answer correctness.
- Question difficulty.
- Repeated performance across different questions.
- Independence of the answer.
- Use of hints.
- Performance over time.
- Successful recall after a delay.

The precise formula, weighting, and thresholds must be separately specified and approved before implementation.

A single correct answer must not automatically mean complete mastery.

8.3 No Forced Progression Locks

A student must not be prevented from accessing a new grammatical concept because another concept has a low mastery score.

The platform may recommend remedial activities, but learning progression must remain accessible.

9. Spaced Repetition — Grammar Review

The system should support reviewing grammatical concepts that the student previously misunderstood.

Example:

A student makes repeated mistakes involving الأسماء الخمسة.

The system may:

1. Record the relevant skill as requiring review.
2. Recommend a suitable explanation or practice activity.
3. Schedule a future review opportunity.
4. Present a different exercise testing the same concept.
5. Update the mastery estimate based on the new evidence.

Rules:

- Do not simply repeat the same question indefinitely.
- Prefer varied exercises that assess the same underlying skill.
- Review scheduling should respond to student performance rather than applying one fixed interval to everyone.
- Spaced repetition must operate outside active examination attempts.
- Review activities must not modify previous examination results.

The exact scheduling algorithm is outside the scope of this contract unless separately approved.

10. Branching Remediation

When a student struggles with a particular grammatical concept, the training experience may provide a short remedial path.

Example:

Original Exercise

Identify the grammatical role of a word in a sentence.

Incorrect Answer

The system identifies the relevant weakness.

Remedial Activity

A short exercise reviews the grammatical rule or relationship.

Guided Practice

The student completes a simpler or more focused exercise.

Return to Learning

The student may try a different exercise testing the original concept.

Important rules:

- Remediation must be predefined, reviewed, and approved.
- It must not be an uncontrolled AI-generated sequence.
- It must not erase the original mistake.
- It must not change the score of the original attempt.
- It must not become an examination path.
- It must not be available during active simulator examinations.

Remediation performance may contribute to the separate educational mastery record according to approved rules.

11. Content Authoring and Administration

The grammar experience must remain manageable through the existing administration system.

The administrator should be able to configure the educational content supported by the existing question model.

Potential authoring capabilities include:

- Sentence text.
- Selectable words or text segments.
- Correct grammatical roles.
- Correct grammatical cases.
- Correct grammatical marks.
- Grammatical explanations.
- Skill associations.
- Hint sequences.
- Partial-credit components.
- Training-specific remedial activities.

These are functional requirements, not a decision to create new database tables or fields.

Before implementation, the current authoring components and question data structures must be inspected.

The implementation must reuse existing capabilities wherever possible.

12. Arabic Language and Mobile-First Requirements

Arabic grammar is highly dependent on correct text presentation.

The interface must support:

- Correct RTL layout.
- Correct Arabic letter shaping.
- Preservation and readable rendering of diacritics.
- Clear display of punctuation.
- Selection of individual Arabic words without corrupting adjacent characters.
- Mixed Arabic and Latin text where required.
- Mobile touch interactions.
- Responsive layouts.
- Readable text at different screen sizes.
- Accessible interaction without relying exclusively on color or drag-and-drop.

The basic learning experience must not depend on audio or animation.

The web implementation must remain compatible with the project's future Android wrapper through Capacitor.

However, Android-specific implementation and testing are deferred until the UX phase is completed.

13. Examination Security and Historical Integrity

The Adaptive Grammar Lab must comply with the existing examination security model.

The following requirements are mandatory:

1. Correct answers must not be exposed before their permitted release time.
2. Simulator mode must not receive hints, correct classifications, or answer-revealing explanations.
3. Official grading must be performed by the server.
4. The client must not be trusted as the authority for official scores.
5. The question content, correct answers, and relevant assessment configuration must be preserved in the examination snapshot as required by the existing architecture.
6. Updating a question must not change the reference answer or content of previously completed examination attempts.
7. No API requests are permitted during an active simulator attempt.
8. Training-only information must never leak into the simulator interface or its data payloads.

The existing snapshot and grading architecture remains authoritative.

14. Artificial Intelligence Boundaries

AI may assist with:

- Suggesting suitable review activities.
- Helping explain a previously misunderstood grammatical concept.
- Recommending exercises from an approved content library.
- Supporting future educational analytics.

AI must not independently:

- Define official answer keys.
- Change approved grammatical reference answers.
- Determine official examination marks.
- Modify published examination questions.
- Generate unverified grammatical explanations and treat them as authoritative.
- Change examination difficulty during an active attempt.

All official answers and grading rules must be based on reviewed, approved, and testable reference data.

15. Integration with the Existing Platform

The Adaptive Grammar Lab must be integrated into the existing platform rather than implemented as an independent system.

The implementation must preserve:

- The existing 15 approved question types.
- The current training and simulator distinction.
- Existing examination lifecycle contracts.
- Existing authentication and authorization rules.
- Existing database conventions.
- Existing question-bank architecture.
- Existing server-side grading responsibilities.
- Frozen contracts C1–C9 v1.1.0.

No new package, framework, external interaction engine, or database migration may be introduced without first establishing the need and obtaining explicit approval.

16. Implementation and Verification Procedure

Implementation must not begin immediately.

The first step is a read-only technical audit of the actual project.

The audit must identify:

1. The existing grammar question type and its exact implementation.
2. Relevant frontend components and their responsibilities.
3. Current question-authoring and editing workflows.
4. Existing question and answer data structures.
5. Existing scoring and grading logic.
6. Existing training and simulator behavior.
7. Existing snapshot implementation.
8. Existing tests and test coverage.
9. Existing skill or performance tracking capabilities, if any.

For every finding, provide:

- Exact file path.
- Component, function, or type name.
- Relevant code evidence.
- Current behavior.
- Gap against this contract.
- Proposed minimal change, if needed.

Do not modify any file during the audit.

After the audit, produce a gap analysis and a proposed implementation plan.

Implementation requires explicit approval.

Changes must be minimal, targeted, and presented through a diff-first process.

Do not modify unrelated files or make broad generated changes.

Do not create a database schema or migration based on assumptions.

Stop and request clarification if an existing frozen contract or data structure prevents compliance.

17. Acceptance Criteria

The Adaptive Grammar Lab is not complete until the following criteria are verified.

A. Interactive Learning

- A student can select individual words in an Arabic sentence.
- The selected word is clearly distinguishable.
- The student can identify grammatical roles.
- The student can identify grammatical cases and marks where required.
- The student can analyze a complete sentence when the exercise requires it.
- Semantic highlighting works correctly with Arabic text.
- Drag-and-drop has an equivalent tap-based alternative.

B. Guided Training

- Immediate feedback is available in training mode.
- Hints appear according to the authored configuration.
- Explanations are displayed at the appropriate learning stage.
- Partial-credit behavior follows the configured marking scheme.
- Remedial activities are available only where configured.
- A student can continue to another concept without being blocked by low mastery.

C. Mastery and Review

- Skills are tracked separately where supported.
- Incorrect answers can identify a skill requiring review.
- A later review can use a different question.
- Review performance does not overwrite previous examination results.
- Mastery is not inferred from one isolated correct answer.

D. Simulator Security

- No hints appear during an active simulator attempt.
- No correct answers or answer-revealing data are exposed.
- No immediate correctness feedback is provided.
- No remedial path is available.
- No API requests occur during the active attempt.
- Official grading remains server-side.
- Historical examination attempts remain unchanged after content updates.

E. Mobile and Arabic UX

- The interface works on narrow mobile screens.
- Arabic RTL presentation is correct.
- Word selection works with touch.
- Text remains readable and correctly shaped.
- The experience does not depend on drag-and-drop, sound, or animation.

F. Architectural Compliance

- No new examination engine is created.
- No approved question type is duplicated.
- Frozen contracts remain unchanged.
- No unapproved database schema changes are introduced.
- Existing tests continue to pass.
- New behavior has appropriate automated coverage.

18. Definition of Done

The Adaptive Grammar Lab can be considered complete only when:

1. The read-only audit has been reviewed.
2. The implementation plan has been approved.
3. All approved changes have been implemented.
4. The relevant automated tests pass.
5. Training behavior has been verified.
6. Simulator security has been verified.
7. Arabic and mobile interactions have been verified.
8. Mastery and review behavior has been verified within the approved scope.
9. No frozen contract has been changed.
10. The final implementation report includes exact changed files, test evidence, remaining limitations, and any unresolved issues.

Final Principle

The Adaptive Grammar Lab must serve three purposes without confusing them:

- Formal examination: measure what the student can do independently.
- Interactive learning: explain, guide, and correct mistakes.
- Long-term mastery: identify what the student has learned and what needs further practice.

These purposes must remain separate in their data, behavior, and reporting, while operating within the existing architecture of Awal Al-Shehada.
